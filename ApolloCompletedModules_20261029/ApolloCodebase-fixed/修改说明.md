# 本次修改

这是基于你上传的源码制作的修改版，解压目录为 ApolloCodebase-fixed。保留原来的 ApolloCodebase-main 文件夹，避免覆盖原版本。

1. AP（持球进攻角色）传球后，使用本次运球更新前的就绪状态判断是否已出球，修复状态先被清除、导致未登记出球的问题。
2. 我方定位球处理中加入 ST（接应角色）的行为入口；我方球门球仍由原守门员逻辑处理。
3. 已被排除的传球人，不会因通信消息声称自己是 AP 而被重新选为 AP。
4. 启停脚本按“项目目录＋队名”记录并验证进程，只停止对应实例。增加 kill_opponent.sh；pack.sh 同样使用新脚本。

本次不改变场地尺寸（仍为 55×36 米）、训练模型、运球参数和守门员策略。原文件备份在 original_before_fix/。

## 在你电脑上使用

先停止当前运行的队伍，保留仿真环境的安装。

将压缩包放到 Windows 下载目录并解压，把其中的 ApolloCodebase-fixed 文件夹放到 Ubuntu 的 ~/robocup/ 下。不要把它放进原 ApolloCodebase-main 目录。

在 Ubuntu 终端编译（复用原项目已安装的 ONNX Runtime）：

```bash
cd ~/robocup/ApolloCodebase-fixed
bash rebuild_local.sh
```

脚本默认查找 ~/robocup/ApolloCodebase-main/deploy/thirdparty/onnxruntime-linux-x64-1.22.0。如实际位置不同，用以下形式指定真实路径：

```bash
ONNXRUNTIME_ROOT=/真实路径/onnxruntime-linux-x64-1.22.0 bash rebuild_local.sh
```

保持你已经跑通的仿真服务器启动方式。服务器运行后，在上述终端启动修改版：

```bash
bash start.sh
```

要启动同一修改版作为另一队，另开 Ubuntu 终端：

```bash
cd ~/robocup/ApolloCodebase-fixed
bash start_opponent.sh
```

这只是两支相同修改版队伍互踢，不是新旧版本对比。默认连接 127.0.0.1:60000；服务器若使用其他端口，把主机和端口作为两个参数传给启动脚本。

停止对应队伍：

```bash
bash kill.sh
bash kill_opponent.sh
```

每个球员日志位于 logs/ 下对应实例目录。启动信息仅表示已尝试创建进程；是否连接成功要看服务器或日志。

## 新旧版本对比

原版本的旧 kill.sh 可能会停止所有同名程序。先把本修改版的 start.sh、start_opponent.sh、kill.sh、kill_opponent.sh、team_processes.sh 这五个脚本复制到原版本目录，替换它的启动脚本（不改它的 C++ 源码和已编译程序）。

原版本目录运行 `bash start.sh`，修改版目录运行 `bash start_opponent.sh`，两队队名不同。停止时各自在对应目录运行相应的新停止脚本。不要使用 original_before_fix/ 中的旧停止脚本。
